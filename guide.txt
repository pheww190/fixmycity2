========================================================================
             MUNICIPAL GRIEVANCE PLATFORM - SETUP & USER GUIDE
========================================================================

FixMyCity is a municipal grievance management platform built with Express 4,
SQLite/MongoDB, JWT authentication, and vanilla JavaScript.

1. PREREQUISITES
----------------
Make sure you have the following installed:
- Node.js (v18 or higher)
- Python 3.x (with Matplotlib and NumPy for Analytics charts)
- SQLite3 (built-in file database: backend/data/database.sqlite) or MongoDB

2. ENVIRONMENT VARIABLES
------------------------
Configure `backend/.env` (see `backend/.env.example` for reference):

- PORT: Server listening port (default: 3000)
- NODE_ENV: Runtime mode ('development', 'production', or 'test')
- JWT_SECRET: Secret key for signing/verifying JWTs. Required in production;
  an ephemeral per-process random secret is generated in development.
- AADHAAR_PEPPER: Secret pepper for deterministic HMAC-SHA256 Aadhaar hashing.
  Raw Aadhaar digits are NEVER stored or returned. Required in production.
- PYTHON_BIN: Python 3 executable path (e.g., 'python' or 'python3')
- SMTP_USER: Email account username for sending OTPs and status updates
- SMTP_PASS: Email app password
- OTP_DEBUG: When 'true' (development only), echoes OTPs in API responses for
  offline testing. Enforced OFF in production.
- MONGO_URI: Optional MongoDB connection string if running MongoDB.

3. INSTALLATION & MIGRATION
---------------------------
In the project root or /backend directory:
> npm install

To migrate legacy unhashed Aadhaar numbers in the database:
> npm run migrate:aadhaar -- --dry-run   # Preview changes without modifying DB
> npm run migrate:aadhaar               # Execute migration and mark accounts verified

4. START THE SERVER
-------------------
> npm start

Server will start at: http://localhost:3000

6. CITIZEN AUTHENTICATION & TWO-STEP OTP FLOW
---------------------------------------------
Citizen authentication is strictly two-step and OTP-based:
- Registration:
  1. POST /api/auth/citizen/register with Name, Aadhaar (Verhoeff-validated),
     Phone, and Email. A 6-digit OTP is generated, hashed at rest (SHA-256),
     and sent via email (or console).
  2. POST /api/auth/citizen/verify with Aadhaar and OTP. On successful
     verification, account is saved to DB and session token issued.
- Login:
  1. POST /api/auth/citizen/request-otp with 12-digit Aadhaar. Returns an
     identical response for registered and unknown Aadhaars to prevent
     citizen enumeration.
  2. POST /api/auth/citizen/login with Aadhaar and 6-digit OTP. Codes expire
     after 5 minutes, allow max 5 attempts, enforce a 60-second cooldown,
     and are single-use.

8. CORE FEATURES & ARCHITECTURE
--------------------------------
- Rule-based keyword classifier for automated department routing.
- Real-time mapping with EXIF GPS extraction from submitted photos.
- Real image signature verification (JPEG, PNG, WEBP) on uploads.
- Department-scoped officer access with fail-closed protection.
- Stored XSS defense with HTML/attribute escaping and safe URL filtering.
- Status workflow validation (Pending -> In Progress -> Resolved/Rejected).
- Strict rate limiting across auth, OTP, registration, complaint filing, and APIs.
- Python Matplotlib analytics chart generation executed serially via stdin.
